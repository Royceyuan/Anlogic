# MAIN-5A PHY/UDP 独立诊断上板验收

## 1. 本轮边界

该 bit 是独立的以太网诊断入口，不包含 HDMI、TF 卡、音频或 MAIN-5 展陈界面，也尚未把以太网控制命令接入主工程。它只验证主板 PHY、RGMII、MDIO、TEMAC 和 UDP 回显链路，避免媒体工程干扰网络问题定位。

- bit：`release/hx4s20_main5a_ethernet_diag.bit`
- SHA-256：`C9535D6556FC6A347DF414C1CA843604D2FE2D02B1E5A676F5A1B43520C813B9`
- FPGA：`EG4S20BG256`
- FPGA 地址：MAC `02:48:58:34:20:01`，IPv4 `192.168.10.1`，UDP `5000`
- 对端地址：IPv4 `192.168.10.2`，UDP `5000`

构建验证：ModelSim 控制面测试通过（两包连续 UDP 回显、单字节回显、发送端未就绪等待、忙时新包隔离及 MDIO 轮询）；TD 6.2.1 最终 setup `+114 ps`、hold `+22 ps`，无时序违例；LUT `4650/19600`（23.72%）、BRAM9K `10/64`、BRAM32K `1/16`、DSP `0/29`。布局布线 DRC 未发现多驱动、局部时钟路由或异常时序路径。

2026-09-25 修订：首版上板收到的 40 字节回包首字节重复、末字节丢失；已按 BRAM 同步读时序提前一拍预读，并修复发送端暂不可用时丢包。电脑测试脚本现会等待首次 ARP、重发超时请求并忽略迟到的旧包。请以本节 SHA-256 判断是否烧录了修订版。

进一步复测的旧版结果曾为 `17/20`，随后 `1/5`；电脑抓包发现仍有旧序号回包延迟到下一轮。上一修订版修复了仿真复现的“发送端忙时新包覆盖待发包长度/缓存”缺陷，并在脚本结果中统计被忽略的旧回包，但上板仍未通过。

后续新 bit 曾出现 `0/20` 且旧回包持续增加；PHY ID `001C/C915`、状态 `ACC2` 表明千兆全双工链路已建立。电脑端临时固定 ARP 邻居后仍为 `0/20`，故 ARP 失效不是唯一原因。本版新增对 UDP 栈、收发 FIFO 和 MAC 的上电/KEY1 复位，以清除可能积压的发送状态。测试前不需在电脑上添加静态 ARP。

本版上板结果：两轮各 `20/20`、本机长测 `1000/1000`，均无旧序号回包；十轮运行后 `SW2:SW1=11` 的 RX/TX 计数一致，拔插网线后仍一致。因此记录 `MAIN-5A PHY/UDP PASS`。这仅覆盖独立诊断链路，不等于 MAIN-5 双板联调通过。

## 2. 烧录前电脑设置

1. 用网线直连电脑和 FPGA 板，建议关闭该网卡的节能功能。
2. 将电脑有线网卡手动设置为：
   - IPv4：`192.168.10.2`
   - 子网掩码：`255.255.255.0`
   - 网关、DNS：留空
3. 暂时断开会抢占 `192.168.10.0/24` 路由的 VPN 或其他网卡。
4. Windows 防火墙若询问 Python 网络权限，允许“专用网络”；不要为测试关闭整个防火墙。
5. 若脚本绑定端口报 `WinError 10013`，检查电脑 UDP 5000 是否被其他程序占用；本机曾由 NI Domain Service 占用，测试前需暂时停止它。

## 3. 板载诊断含义

板载 LED 硬件为高电平点亮；当前诊断 bit 的输出取反。丝印 LED1～LED4 对应代码 `led[0]`～`led[3]`，以下按已验证 bit 的实测解释：

| LED | 含义 | 正常现象 |
|---|---|---|
| LED1 / `led[0]` | 心跳 | 持续闪烁，证明 50 MHz 控制逻辑运行 |
| LED2 / `led[1]` | PHY link | 插线且 link=1 时熄灭，拔线亮起（极性反向，保留现有 bit） |
| LED3 / `led[2]` | 收包翻转 | 每收到一个 UDP 包翻转一次，空闲时可能常亮 |
| LED4 / `led[3]` | 发送确认翻转 | 每次应用发送确认翻转一次，空闲时可能常亮 |

SW1、SW2 选择八位数码管的 16 位十六进制诊断值：

| SW2:SW1 | 数码管低四位 | 预期/解释 |
|---|---|---|
| `00` | PHY ID1 | RTL8211E 通常为 `001C` |
| `01` | PHY ID2 | 本板预计接近 `C915`，低位包含版本号 |
| `10` | PHY 状态寄存器 17 | bit10=link，bit11=已解析，bit13=全双工，bit15:14=`10` 表示 1000 Mb/s |
| `11` | `RX计数:TX计数` | 每次成功回显两者同步递增；8 位自然回卷 |

KEY1 清空应用层回显缓存、计数器和 MDIO 显示状态，同时复位 UDP 栈、收发 FIFO 与 MAC；松开后各时钟域同步释放。复位期间链路灯可能短暂变化。若 PHY 本身异常，重新烧录或断电重启板卡。

## 4. UDP 回显测试

在仓库根目录执行：

```powershell
py -3 .\tools\udp_echo_test.py
```

默认连续发送 20 包；也可指定包数：

```powershell
py -3 .\tools\udp_echo_test.py 1000
```

通过标准：

- 输出最终为 `result: 20/20`（长测则为指定包数全部通过）；
- LED3、LED4 都随包翻转；
- `SW2:SW1=11` 时 RX、TX 计数一致；
- 网线拔出后 LED2 亮起，重新插入后熄灭；
- KEY1 后再次运行脚本仍可全数回显。

`ping 192.168.10.1` 不是本轮判据；当前诊断只承诺 ARP 与 UDP 回显，不承诺 ICMP Echo。

## 5. 故障分层

| 现象 | 优先检查 |
|---|---|
| 无心跳 | bit 是否正确烧录、50 MHz 时钟和板卡供电 |
| 有心跳、无 link | 网线、电脑网卡、PHY 供电/焊接、MDIO ID 是否有效 |
| link 正常、RX 不变 | 电脑静态 IP、路由冲突、防火墙、发包目标是否为 `.1:5000` |
| RX 变化、TX 不变 | UDP 应用握手或发送 FIFO；记录 SW=`11` 数值 |
| RX/TX 都变化但脚本超时 | 电脑端绑定地址、防火墙、ARP 表或回包目的地址 |
| ID 为 `FFFF`/`0000` | MDIO 上拉、PHY 地址 1、MDC/MDIO 管脚连接 |

上板反馈请至少附：link LED 状态、四个拨码页数值、脚本最终统计和是否能在拔插网线后恢复。
