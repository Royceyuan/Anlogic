## 4. 副板分阶段任务与验收目标

### SECONDARY-0：独立 HDMI 工程壳

任务：

- 新建副板顶层、ADC、SDC、P&R 和 bitgen 脚本。
- 使用 50 MHz 输入和 HDMI1 输出。
- 显示 1280×720 彩条、中心线和边界线。
- LED0 显示心跳，LED1 显示视频复位释放，数码管显示 `S000` 或等效阶段码。
- 不接 TF、SDRAM、以太网和文物页面。

仿真至少覆盖：

- 水平/垂直总周期。
- 有效区恰为 1280×720。
- `frame_tick` 每帧一次。
- 复位释放后视频时序稳定。

上板验收：

- 显示器识别为 1280×720。
- 彩条位置固定，四边和中心线无抖动、错位或裁切。
- 连续运行 30 分钟无黑屏和重新握手。

通过标志：`SECONDARY-0 BOARD PASS`。

### SECONDARY-1：五件文物独立 5 秒轮播

任务：

- 接入副板 TF/SPI、SDRAM 和五图缓存。
- 读取 `IMAGE0.BMP`～`IMAGE4.BMP`。
- 五张图全部有效后启动轮播。
- 每页停留 5 秒，顺序固定为 0→1→2→3→4→0。
- 切页只在视频帧边界发生。
- 断开网线或主板掉电不改变本地轮播。
- 媒体未就绪页不得显示上一页内容冒充当前页。

推荐测试：

- 把自动周期在仿真中缩短，验证首尾循环和帧边界提交。
- 分别让 0～4 号图片缺失，确认状态码能区分文件不存在和 BMP 格式错误。
- 验证 1920×1080、1080×1080 等不同源尺寸等比适配且不拉伸。

上板验收：

- 五页均能显示。
- 实测每页停留 `5.0 s ± 1 帧`。
- 连续 20 个切页周期不花屏、不撕裂、不出现旧页残留。

通过标志：`SECONDARY-1 BOARD PASS`。

### SECONDARY-2：信息页、展厅地图和预设导航

建议版式：

```text
┌──────────────────────────────┐
│ 文物名称 / 年代 / 类别       │
├────────────────┬─────────────┤
│ 文物图片或细节 │ 展厅简图    │
│                │ 当前点●     │

├────────────────┴─────────────┤
│ 简介 / 展柜号 / LINK 状态     │

```

任务：

- 五件文物分别使用固定信息页。
- 地图为预设路线，不做实时定位和动态最短路径。
- 页面底部预留 `LINK WAIT / LINK OK / LINK LOST` 区域。
- 轮播计时器独立于 LINK 状态和主板文物索引。
- 页面素材缺失时显示明确占位，不复用上一件文物的名称或地图。

最小实现优先使用 PC 端预排版 BMP。若资源允许，再把 LINK 状态和紧急提示做成 FPGA 实时叠加层；不要一开始就做中文字库和复杂矢量地图。

通过标志：`SECONDARY-2 BOARD PASS`。

### SECONDARY-3：副板本地紧急状态

在接以太网前，先使用副板本地按键或拨码模拟 `emergency_set` 和 `emergency_clear`。

任务：

- 紧急状态优先级高于轮播、切页和 LINK 状态。
- 紧急页显示当前位置、最近出口、预设疏散路线、方向箭头和高对比警示色。
- 紧急期间冻结普通轮播索引和计时器，或明确规定解除后从第 0 页重新开始；推荐从第 0 页重新开始，状态最可预测。
- 解除紧急后清除紧急状态，不保留半完成转场。
- 紧急画面不能依赖主板图片或网络持续在线。

通过标志：`SECONDARY-3 BOARD PASS`。

### SECONDARY-4A：PHY、MDIO 和 RGMII 物理链路

此阶段使用独立 Ethernet 诊断顶层，不与 HDMI/TF 主链同时集成。

任务：

- MDC/MDIO 读取 PHY 地址 1。
- 读取 PHY ID、Basic Status 和协商结果。
- 显示 `LINK WAIT / LINK 10 / LINK 100 / LINK 1000 / LINK ERROR`。
- 验证 RGMII RXC 和数据接收；实现最小以太网帧收发或 MAC 回环。
- 确认 RGMII TX/RX 时钟延迟方案并写入 SDC。
- 不使用 false path 或 multicycle 掩盖 RGMII 真实数据路径。

通过标志：`SECONDARY-4A PHY PASS`。

### SECONDARY-4B：Ethernet/IPv4/UDP 与应用协议

任务：

- 实现固定 MAC、固定 IPv4 和 UDP 5000。
- 实现本文第 7 节的 MBP1 报文解析、CRC16、序号、重复包处理和 ACK。
- 先由 PC 测试器模拟主板，再与真实主板联调。
- 网络解析错误不得阻塞 HDMI、TF 或轮播状态机。
- RGMII RX 时钟域通过异步 FIFO 进入 50 MHz 控制域；控制状态只在安全边界提交到视频域。

通过标志：`SECONDARY-4B UDP PASS`。

### SECONDARY-4C：主副板联调

任务：

- 主板正常状态只更新副屏的状态文字，不修改副屏轮播索引。
- 主板紧急事件立即抢占副屏普通页面。
- 紧急解除后副屏从默认轮播页重新开始。
- 网线断开 2 秒后显示 `LINK LOST`；普通状态下继续本地轮播。
- 紧急状态中断链时保持紧急页，不能因超时自动清除。
- 网线恢复后重新 HELLO，并用完整状态快照纠正双方状态。

通过标志：`SECONDARY-4 BOARD PASS`。

## 5. 板载以太网硬件事实与管脚

已从开发板原理图核对：

- PHY：RTL8211E-VB-CG。
- 网口变压器/RJ45：HR911130A。
- PHY 晶振：25 MHz。
- MAC/PHY 接口：RGMII，双沿采样。
- MDIO 管理接口存在。
- RGMII/MDIO 侧由原理图配置为 2.5 V 域；ADC 中应使用与实际 VCCIO 一致的 2.5 V I/O 标准，不能照搬主板普通 GPIO 的 `LVCMOS33`。
- PHY 地址绑带为 `001`，即 MDIO 地址 1；仍应在上板时轮询地址 1 并读取 PHY ID 验证。
- PHY 硬复位脚由板上 RC 网络处理；当前原理图未证明它由 FPGA 直接控制。需要复位 PHY 时优先使用 MDIO BMCR bit15 软件复位。
- RTL8211E 默认支持 Auto MDI/MDIX；网线直连仍需实际验证协商。

建议副板顶层端口和 FPGA 管脚如下：

| 顶层端口 | FPGA 管脚 | 方向 | 说明 |
|---|---:|---|---|
| `eth_txd[0]` | T4 | 输出 | RGMII TXD0 |
| `eth_txd[1]` | T6 | 输出 | RGMII TXD1 |
| `eth_txd[2]` | M7 | 输出 | RGMII TXD2 |
| `eth_txd[3]` | T8 | 输出 | RGMII TXD3 |
| `eth_tx_ctl` | T7 | 输出 | RGMII TXCTL |
| `eth_tx_clk` | T12 | 输出 | RGMII TXC，千兆时 125 MHz |
| `eth_rxd[0]` | P6 | 输入 | RGMII RXD0 |
| `eth_rxd[1]` | M6 | 输入 | RGMII RXD1 |
| `eth_rxd[2]` | T9 | 输入 | RGMII RXD2 |
| `eth_rxd[3]` | N9 | 输入 | RGMII RXD3 |
| `eth_rx_ctl` | T13 | 输入 | RGMII RXCTL，同时为 PHY 地址绑带 AD2 |
| `eth_rx_clk` | T14 | 输入 | PHY 输出的 RGMII RXC |
| `eth_mdc` | L13 | 输出 | MDIO 管理时钟 |
| `eth_mdio` | M13 | 双向 | MDIO 管理数据 |

RGMII 时钟要求：

- 1000M 时 TXC/RXC 为 125 MHz，四位数据在上升沿和下降沿各传一组半字节。
- MDC 建议由 50 MHz 分频到不高于 2.5 MHz。
- RTL8211E 支持 TX/RX 各 2 ns 内部时钟延迟，但开发板实际绑带必须通过 MDIO/波形或已验证例程确认。
- TXC/RXC 输入输出延迟必须写入独立 SDC，并依据 PHY 数据手册和实际延迟模式约束。
- 第一次联调若直连不上，应先读 MDIO 的链路、协商、速度和双工状态，不要先改 UDP 状态机。

| 子网掩码 | `255.255.255.0` | `255.255.255.0` |
| 网关 | 不使用 | 不使用 |
| UDP 源/目的端口 | 5000 | 5000 |
| IPv4 TTL | 64 | 64 |
| 最大 MBP1 UDP 负载 | 256 bytes | 256 bytes |

实现约束：

- 使用 Ethernet II、IPv4、UDP。
- IPv4 不使用 options，不允许分片，DF=1。
- 两板已知对方固定 MAC，因此板间第一版不依赖 ARP。
- 为 PC 调试实现 ARP Reply，或在 PC 上配置静态 ARP；不能让是否完成 ARP 阻塞两板直连。
- IPv4 头校验和必须正确。
- IPv4 下 UDP checksum 第一版固定发送 `0x0000`，接收端接受 `0x0000`；数据完整性由 Ethernet FCS 和 MBP1 CRC16 共同保证。
- 多字节字段全部使用网络字节序，即高字节在前。
- 未识别 EtherType、IP 协议、端口、版本或命令时静默丢弃并累加错误计数，不得影响显示链。

## 7. MBP1 应用层报文协议

协议名：Museum Board Protocol v1，简称 MBP1。
承载：UDP payload。
协议版本：`0x01`。

### 7.1 固定头格式

每个 MBP1 报文由 20 字节头、可变 payload 和 2 字节 CRC16 组成：

| 偏移 | 长度 | 字段 | 固定/说明 |
|---:|---:|---|---|
| 0 | 1 | `magic0` | `0x4D`，ASCII `M` |
| 1 | 1 | `magic1` | `0x42`，ASCII `B` |
| 2 | 1 | `version` | `0x01` |
| 3 | 1 | `msg_type` | 见 7.3 |
| 4 | 1 | `flags` | bit0 ACK_REQ，bit1 IS_ACK，bit2 RETRANSMIT，其余必须为 0 |
| 5 | 1 | `header_len` | 固定 `0x14`，即 20 bytes |
| 6 | 2 | `payload_len` | 0～256，大端 |
| 8 | 4 | `seq` | 发送方递增序号，大端，允许回绕 |
| 12 | 4 | `boot_id` | 每次 FPGA 启动改变的 32 位会话标识 |
| 16 | 4 | `uptime_ms` | 发送方启动后毫秒数，大端，允许回绕 |
| 20 | N | `payload` | 长度必须等于 `payload_len` |
| 20+N | 2 | `crc16` | 大端 |

`boot_id` 可以由自由运行计数器、PHY 链路启动时间和固定板号混合产生；不要求密码学随机，但同一块板连续两次启动不应固定为同一个值。

### 7.2 CRC16 冻结参数

使用 CRC-16/CCITT-FALSE：

```text
poly   = 0x1021
init   = 0xFFFF
refin  = false
refout = false
xorout = 0x0000
```

计算范围为从 `magic0` 到 payload 最后一个字节，不包含 CRC 字段自身。标准校验向量：

```text
ASCII "123456789" -> 0x29B1
```

主副板 testbench 必须共享该校验向量。

### 7.3 消息类型

| `msg_type` | 名称 | 方向 | ACK_REQ | payload 长度 |
|---:|---|---|---|---:|
| `0x01` | `HELLO` | 双向 | 是 | 12 |
| `0x02` | `HEARTBEAT` | 双向 | 否 | 16 |
| `0x03` | `STATUS_QUERY` | 双向 | 是 | 0 |
| `0x04` | `ACK` | 双向 | 否 | 8 |
| `0x10` | `ARTIFACT_SELECT` | 主→副 | 是 | 4 |
| `0x11` | `LECTURE_STATE` | 主→副 | 是 | 4 |
| `0x12` | `PLAYBACK_STATE` | 主→副 | 是 | 8 |
| `0x13` | `DISPLAY_PRESET` | 副→主，可选 | 是 | 4 |
| `0x20` | `EMERGENCY_SET` | 主→副 | 是 | 4 |
| `0x21` | `EMERGENCY_CLEAR` | 主→副 | 是 | 4 |
| `0x30` | `LINK_STATUS` | 副→主 | 否 | 4 |

### 7.4 payload 定义

`HELLO`：

| 偏移 | 字段 |
|---:|---|
| 0 | role：主板 `0x01`，副板 `0x02` |
| 1 | board_id：主板 1，副板 2 |
| 2 | min_version：`0x01` |
| 3 | max_version：`0x01` |
| 4～7 | build_id，32 位大端 |
| 8～11 | capability 位图，32 位大端 |

capability 建议位定义：bit0 HDMI，bit1 TF，bit2 audio，bit3 emergency，bit4 display-preset，bit5 Ethernet RX，bit6 Ethernet TX。

`HEARTBEAT`：

| 偏移 | 字段 |
|---:|---|
| 0 | mode |
| 1 | artifact_id，0～4，无效为 `0xFF` |
| 2 | lecture_phase |
| 3 | playback_state |
| 4 | emergency_active，0/1 |
| 5 | display_preset，0～3 |
| 6 | error_code |
| 7 | 保留，必须为 0 |
| 8～11 | audio_frame，32 位大端；无音频时为 0 |
| 12～13 | emergency_id，16 位大端 |
| 14～15 | 保留，必须为 0 |

`ARTIFACT_SELECT`：`artifact_id, confirmed, source, reserved`。`confirmed=1` 表示主板已确认进入讲解；该消息只更新副屏状态文字，不改变副屏轮播页。

`LECTURE_STATE`：`artifact_id, lecture_phase, state, reason`。`reason`：0 正常、1 用户返回、2 紧急抢占、3 错误。

`PLAYBACK_STATE`：前四字节依次为 `artifact_id, playback_state, lecture_phase, display_preset`，后四字节为 `audio_frame`。

`DISPLAY_PRESET`：`preset, apply_scope, reserved0, reserved1`。第一版 `preset=0～3`，`apply_scope=1` 表示主屏。紧急状态下主板必须拒绝，ACK 返回 `BUSY`。

`EMERGENCY_SET/CLEAR`：前两字节为 `emergency_id`，第三字节为 `route_id` 或 clear reason，第四字节为 `alarm_mode` 或 0。`CLEAR` 只有在 ID 与当前紧急事件一致时才生效，防止迟到旧包清除新警报。

`ACK`：

| 偏移 | 字段 |
|---:|---|
| 0～3 | `acked_seq`，32 位大端 |
| 4 | `acked_type` |
| 5 | result：0 OK，1 BAD_CRC，2 BAD_LENGTH，3 UNSUPPORTED，4 BUSY，5 INVALID_STATE |
| 6 | receiver_mode |
| 7 | 保留，必须为 0 |

### 7.5 状态枚举

```text
mode:
0 BOOT
1 OVERVIEW_OR_CAROUSEL
2 LECTURE
3 EMERGENCY
4 ERROR

lecture_phase:
0 FULL_FIRST
1 DETAIL1
2 DETAIL2
3 DETAIL3
4 FULL_FINAL
255 NONE

playback_state:
0 STOPPED
1 PLAYING
2 PAUSED
3 TRANSITION
4 FINISHED
```

### 7.6 发送、ACK、重复包和超时

- `seq` 每发送一包加 1；重传保留原 `seq` 并设置 `RETRANSMIT`。
- 接收端用 `(boot_id, seq)` 判断重复包。
- 重复的有效命令不得再次改变状态，但仍须重发 ACK。
- 收到新的 `boot_id` 时清空该发送方的去重窗口，并重新执行 HELLO。
- HEARTBEAT 周期 500 ms。
- 2 s 未收到合法 HEARTBEAT，状态变为 `LINK LOST`。
- 普通 ACK_REQ 报文 100 ms 未确认则重发，最多 10 次；之后由 HEARTBEAT/STATUS_QUERY 恢复完整状态。
- `EMERGENCY_SET` 和 `EMERGENCY_CLEAR` 每 100 ms 重发，直到 ACK 或被更新的紧急事件取代。
- HEARTBEAT 是周期性完整状态快照，用于修复丢包后的状态差异。
- 副板在紧急状态中断链时保持紧急页；只有匹配的 CLEAR、本地维护复位或重新上电才能清除。

## 8. 关于“副板按钮控制主板亮度/对比度”的结论

### 8.1 不会降低主板图像处理资源

副板按钮只负责产生 `DISPLAY_PRESET` 命令。主板仍必须对主屏每个像素执行亮度、对比度和风格运算，因此不能删除 `rgb888_adjust.v`，也不能减少这部分像素处理资源。

当前 `rgb888_adjust.v` 已使用移位和加法，不使用 DSP；把按键采集移到副板最多减少极少量消抖和控制寄存器，却会在主板增加 RGMII、MAC、IPv4、UDP、CRC、FIFO 和命令解析。行缓存 BRAM 化并移除字幕背景后，主板路由后 slice 占用已降至 72.50%，但这种控制迁移本身仍会增加而不是降低主板资源。

### 8.2 可作为交互创新，但应放到最后

若希望副屏兼作控制面板，可以在双板 Ethernet 稳定后启用 `DISPLAY_PRESET`：

1. 副板本地按钮消抖后发送 0～3 档预设。
2. 主板校验命令，紧急状态下拒绝。
3. 主板在视频帧边界应用参数。
4. 主板发送 ACK。
5. 下一包 HEARTBEAT 回报实际 `display_preset`，副板据此更新 UI。

主板 KEY1 仍保留为离线回退。正常状态下采用“最后一个被主板接受的本地或远程操作生效”；紧急状态优先级最高。

### 8.3 真正降低主板资源的途径

若 MAIN-5 无法 P&R，应按以下顺序处理：

1. 先测量 Ethernet 独立顶层资源，采用固定 MAC/IP/UDP，避免通用网络栈。
2. 只实现控制报文所需的最小 RX/TX 缓冲，不缓存完整大包。
3. 对主板现有逻辑做综合报告驱动的优化，不能凭感觉删除功能。
4. 必要时减少主屏画面预设数量或关闭非核心 OSD/波形功能，但必须经用户确认。
5. 不通过副板处理主屏像素；那会变成板间视频传输，违背当前架构并显著增加带宽和联调风险。

## 9. 主副板职责和状态权威

| 状态/功能 | 权威来源 | 断链行为 |
|---|---|---|
| 主屏总览、讲解、暂停、返回 | 主板 | 主板继续本地工作 |
| 主屏亮度/对比度预设 | 主板 | KEY1 仍可本地调整 |
| 副屏 5 秒轮播索引 | 副板 | 继续轮播 |
| 副屏地图和信息页 | 副板本地 TF | 继续显示 |
| 紧急进入/解除 | 主板 SW4 | 副板断链时保持最后已确认的紧急状态 |
| LINK 状态 | 各板本地 PHY+HEARTBEAT | 显示 LINK LOST，不伪造 LINK OK |

副屏正常轮播不跟随 `ARTIFACT_SELECT`。副屏可以显示“主屏正在讲解：四羊方尊”，但自身 5 秒轮播仍独立推进。

## 10. 联调顺序和测试矩阵

严格按以下顺序联调：

1. 两块板分别完成 HDMI 基线。
2. 副板完成本地轮播、地图和本地紧急模拟。
3. 主副板分别完成独立 Ethernet PHY/MDIO/RGMII 诊断。
4. 用 PC 分别测试两块板的 UDP 收发、CRC 和 ACK。
5. 网线直连，先只跑 HELLO/HEARTBEAT。
6. 再接普通状态消息。
7. 最后接紧急消息和可选 `DISPLAY_PRESET`。

必须完成的异常测试：

| 场景 | 预期结果 |
|---|---|
| CRC 错误 | 丢包、错误计数加 1，显示和轮播不受影响 |
| payload 长度错误 | 丢包或 NACK，不越界写状态寄存器 |
| 重复包 | 不重复执行，重新 ACK |
| 乱序旧包 | 不覆盖更新状态 |
| 主板重启 | 副板检测新 boot_id，重新 HELLO 和同步 |
| 副板重启 | 本地轮播先启动，链路建立后同步状态 |
| 普通状态拔网线 | 2 秒后 LINK LOST，副屏继续轮播 |
| 紧急状态拔网线 | 副屏保持紧急页 |
| 丢失 EMERGENCY_SET | 主板重传，HEARTBEAT 状态也可纠正 |
| 丢失 EMERGENCY_CLEAR | 主板持续重传，旧 ID 不能清除新事件 |
| 连续快速按键 | 主板只应用合法预设，副板以 ACK/HEARTBEAT 显示最终值 |
| 10/100M 意外协商 | 显示明确速度，不按 1000M 时钟假设继续工作 |

长稳测试至少 30 分钟，并反复执行：

- 五文物轮播。
- 主板进入、暂停、继续和退出讲解。
- 紧急进入和解除。
- 网线插拔。
- 一块板复位，另一块不复位。
- 副板远程画面预设命令（若启用）。
