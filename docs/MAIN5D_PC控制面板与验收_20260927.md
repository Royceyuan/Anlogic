## 2. 启动步骤

1. 主板与电脑有线网口连接，保持 TF 卡和 HDMI 显示屏正常工作。
2. 电脑对应有线网卡 IPv4 地址设为 `192.168.10.2`，子网掩码 `255.255.255.0`，此直连测试不需要默认网关。主板固定 `192.168.10.1`，双方 UDP 端口均为 `5000`。
3. 关闭旧 UDP/MBP1 测试器和其他控制面板窗口，只运行一个测试端。
4. PowerShell 执行：

```powershell
cd D:\VSCode\CodeFiles\Git_TD\Anlogic
py -3 .\tools\mbp1_pc_control.py
```

5. 点击“连接 / 重连”。应显示“已连接”，随后出现主板实际状态，控制按钮解锁。面板持续发送 500 ms 心跳，不需反复运行脚本。

使用 Python 标准库 Tkinter，无第三方包。若 Python 未安装 Tkinter，使用带 Tcl/Tk 的官方 Python 安装。绑定失败时按提示检查网卡 IP、端口占用和 Windows 保留端口。WinError 10013 不等于 FPGA 故障，不建议直接关闭防火墙；可按需允许当前 Python 在该测试网络收发 UDP 5000。

只读排查命令：

```powershell
Get-NetIPAddress -AddressFamily IPv4
Get-NetUDPEndpoint -LocalPort 5000 -ErrorAction SilentlyContinue
netsh interface ipv4 show excludedportrange protocol=udp
```

2026-09-27 实机排查发现 NI 的 `NIDomainService`（`nidmsrv.exe`）占用 `0.0.0.0:5000`，导致 WinError 10013；网卡 IP 正确且 5000 不属于保留端口。新脚本在创建窗口之前检查绑定，失败时只在终端提示，不再触发 Tk 二次销毁异常。

若再次核实是该服务占用，先结束依赖 NI 域服务的工作，再在**管理员 PowerShell** 中临时停止它（会影响依赖该服务的 NI 软件，不修改启动类型）：

```powershell
Stop-Service -Name NIDomainService
Get-NetUDPEndpoint -LocalPort 5000 -ErrorAction SilentlyContinue
```

端口空闲后，在原终端重新运行控制面板。完成测试、关闭面板后，在管理员 PowerShell 恢复服务：

```powershell
Start-Service -Name NIDomainService
```

不要使用强制共享端口或只修改 PC 端口来绕过占用；当前 FPGA 的固定对端端口仍为 5000。

## 3. 如何操作和观察

### 画面预设与四项参数

- 点击“标准 / 明亮 / 高对比 / 柔和”，图片应改变；字幕、OSD 不应随图片调色一起改变。
- 编辑四项百分比后点击“应用四项编辑值”。每次发送完整四参数，协议仍使用离散索引，不是单参数增量。亮度是满量程加性偏移，色温是负冷正暖强度；主屏第三行 B/C/S/T 依次显示亮度、对比度、饱和度、色温。
- 索引是 FPGA 离散档位，不是百分比或 Kelvin。标准值依次为 `3、2、3、3`；饱和度 0 可用于观察明显的去色效果。恢复时点击“标准”。
- 编辑框只代表待发送值，**底部“实际回报”才是主板报告的状态**。点“回报值填入编辑框”可基于当前生效状态继续微调。
- ACK=0 表示已接受，不等于视口已经显示；面板等待实际目标值匹配后即可下一操作，取消固定等待。若 1.5 秒未确认，解除等待并提示检查回报，不无限锁键。

### 1×/2× 视口平移

1. 在主板选择已就绪文物，KEY2 进入讲解，等转场结束。
2. 主板 KEY1 切换 1×/2×，KEY2 暂停后仍可缩放、调参和平移。
3. 等面板倍率与阶段更新，点击方向键或“视口居中”。
4. 小步 20、大步 40 个规范化源像素（勾选“大步”切换）；范围 X 为 `-240～240`，Y 为 `-135～135`。视口向右，图片内容本身向左移动。
5. 1× 平移会露出背景；2× 限定在源图内部。总览不平移；切换倍率或阶段归中。PC 不负责倍率、选择文物或控制讲解，这些仍用主板按键。

视口命令携带当前文物、阶段和预期倍率；主板拒绝不匹配命令。面板不缓存忙状态下点击供以后执行，字幕错误仍显示，但不一概禁止图像控制。

### 状态数字说明

| 字段 | 含义 |
|---|---|
| 模式 | 0 启动、1 总览、2 讲解、3 应急、4 错误 |
| 阶段 | 0 全貌、1～3 细节、4 最终全貌、255 总览 |
| 播放状态 | 0 停止、1 播放、2 暂停、3 转场、4 结束 |
| 速度代码 | 0 未知、1 10M、2 100M、3 1000M |
| 存储状态 | 0 启动、1 就绪、2 忙、3 错误 |

应急、恢复、转场时可能显示 BUSY；待结束后重新点击，不是网络断开。INVALID_STATE 表示上下文或参数不匹配，应等待新状态后再操作。

## 4. 断线与可靠性边界

- 同时只发一条待确认命令；100 ms 重传同一序号，最多发送 10 次。不会因重传累加偏移。
- 连续约 2 s 没有合法主板心跳即禁用控制，清除待确认事务。重新插线后点击“连接 / 重连”，创建新 PC 会话，不回放旧命令，也不把编辑框旧值自动写入主板。
- 主板重启后同样重连。面板会确认 HELLO、PLAYBACK_STATE 请求，持续接收 HEARTBEAT、DISPLAY_STATUS 和 DIAGNOSTIC_STATUS。
- 校验来源 IP/端口、长度和 CRC；丢弃乱序状态和错误会话 ACK。UDP CRC 和固定地址不是身份认证，只用于可信的本地直连网络。
- ACK 超时不能证明命令未执行；先查看实际回报或重连查询，不要据此反复点击。

## 5. 验收顺序

1. 总览依次选四预设，核对画面和回报；恢复标准。
2. 四参数分别作明显调整并恢复，核对图片变化、OSD/字幕颜色不受影响。
3. 进入讲解并暂停，1×/2× 切换、四向平移、居中、边界停止；核对 1× 露底、20/40 步长。
4. 切换图片、自然结束、重复讲解、重新预载，原音画字幕和转场不受影响。
   在转场开始时尝试发送预设或四参数，若返回 BUSY，待转场结束后再次操作；应无需重新预载即可调参及平移。自定义后选四预设，OSD 应退出 CUSTOM。
5. SW4 进入应急，调参和平移不执行；解除后等新状态再操作，确认无旧命令回放。
6. 拔线后面板控制失效但主板继续本地运行；插线、重连后恢复操作；主板 KEY4 恢复后复测。

请反馈失败时的文物、阶段、操作顺序、ACK 文字和实际回报截图。完整实板验收后再标记 MAIN-5D 通过；本工具本地测试不能替代上板验证。

## 6. 本地回归

```powershell
py -3 .\tools\test_mbp1_pc_control.py
```

仅使用本机回环 UDP，不接触主板：验证会话、心跳、板端请求 ACK、三种控制包、同序号重传、BUSY 后恢复、越界拒绝、暂停下 1×/2× 的 20/40 步长、应急拦截、CRC/旧序号/错误会话过滤、目标值确认、超时解除等待和重连。窗口启动另作 Tkinter 冒烟检查；不能替代 PC→实板控制验收。

FPGA 定向回归入口：

- `sim/run_main5_remote.do`：暂停缩放/平移、预设和自定义切换、命令接受与转场开始竞争、BUSY 后下一命令恢复。
- `sim/run_main5_pan_stream.do`：全尺寸连续像素流，1× 正负及极限偏移露底、2× 边界、无读流下溢。
- `sim/run_museum_status_osd.do`：百分比查表、第三行字符和背景、像素流水线。
- `sim/run_main5_osd_vendor.do`：官方 BRAM32K 模型核验中文 512 行、ASCII 256 行及显示流水线；中文和百分比字符共用一块双口 ROM。
- `sim/run_main5_video_timing.do`、`sim/run_main5_subtitle_timing.do`：旧显示/字幕路径等价回归。
- `sim/run_subtitle_tf_card.do`：只读 E 盘五个真实 SUB 文件，经生产字幕读取器回放完整字幕，并覆盖模拟跨簇访问。

本轮 E 盘 SUB0～SUB4 的格式和长度校验通过，完整回放分别读取 25/28/30/31/31 条字幕。该测试不能验证实板 SD 电气链路或真实 FAT 簇链，因此没有认定偶发字幕错误的根因已修复。DIAGNOSTIC_STATUS 第 7 字节新增 bit0 文件错误、bit1 格式错误，用于后续板测区分；字幕错误仍提示，但不再令 PC 图像控制永久锁定。TF 文件及音画时间轴未修改。
