# 副板TF离线视频独立验证

这是接在原生4位测速之后的独立播放工程，不是正式博物馆版本。工程入口 `secondary_tf_video.al`，候选位流 `secondary_tf_video.bit`。显示器仍接副板HDMIB，不需要电脑HDMI、USB串口或播放器软件。

候选bit已生成，SHA256 `83c61e691c8c7c1e5c03ccb3ccbf30b15010c7dfce88067be4e8f5ee89974999`。seed=8，setup +0.104ns、hold +0.037ns、TNS均0；4933 LUT、3285寄存器、8 BRAM9K、0 DSP、2 PLL。保留与正式博物馆版相同的SDRAM IP位置迁移警告，以及仅通往SDRAM转发时钟的局部布线警告，其余新增严重警告仍拒绝生成。上述资源是独立工程总量，不能直接视为正式工程的新增量。

## 使用

1. TF根目录保留已准备的 `VIDEO0.BIN`，无需删除图片或格式化卡。
2. 使用JTAG临时下载本目录播放bit，不烧写Flash。下载后拔插TF卡，再按副板KEY1重新初始化。
3. 正常情况下自动循环播放越王勾践剑影片。副板KEY2暂停/继续，KEY1重新从头初始化。其余按键/拨码在此独立验证工程中不使用。
4. 观察至少一个完整循环（约82.37秒）、运动是否流畅、有没有花屏/撕裂、KEY2暂停/继续后是否正常。若失败，回报画面、LED及完整8位数码管读数。

本片为静音RGB565视频；此版本不产生独立讲解音轨。它暂不运行以太网、原轮播/简介/说明页/应急及PC直通，用于分离验证新的视频存储链路。正式工程、release位流和Flash均不被本工程替换。

## 数码管与LED

| 页面 | 含义 |
|---|---|
| A0xxxx00（未找到视频前） | SD和文件读取阶段 |
| A000000F | 已初始化、高速模式、SDRAM就绪、画面已发布；运行中正常状态 |
| A000001F | 上述状态且暂停 |
| B0xxxxxx | 文件侧下一帧编号，十六进制；允许比实际显示提前预读 |
| C00009A7 | 本样片共2471帧 |
| D0xxxxxx | 已完成交接的帧数，十六进制；循环时继续累计 |
| F0ss00ee | 原生SD错误，ss阶段、ee错误码 |
| F1ss00ee | FAT/MVID错误：01读长不足，02签名，03卷格式，04目录项，05未找到，06簇链，07视频头/长度，08卷边界，E0底层SD错误 |
| F20000ee | 帧写入错误：01 FIFO满，02上游错误，03字节过多，04帧不完整 |
| F3000001 | 行缓存读空或交接期间仍有未完成行读取 |

LED1心跳；LED2已找到并验证视频头；LED3至少一帧已交接显示；LED4错误。文件读取/帧写入出错后不发布该帧，已显示的完整帧继续保留，需KEY1复位重试。行缓存读空采用洋红色提示，不能把它记录为正常播放。

## 实现边界

- 仅只读SD v2、512字节扇区、FAT32；支持首个MBR分区或无MBR卷、有效FAT选择、碎片化根目录和文件簇链。根目录扫描上限4096扇区。
- 文件名固定为根目录短名 `VIDEO0.BIN`。校验MVID版本、640×360、30/1fps、RGB565大端、静音标志、头CRC32、文件长度与簇边界；不是在FPGA上解码MP4/H.264。
- 视频A/B位于SDRAM尾部字地址1843200、1958400，各115200个32位字，没有占用原四个720p图片槽。此验证工程中尚未同时运行原图片管理器。
- 100MHz原生4位SD → FAT32分段连续读 → RGB565字打包 → 已有50MHz SDRAM控制器 → 两行缓存 → 2倍最近邻放大 → 已有75MHz/375MHz本地HDMI编码发送。
- 整帧读卡CRC和SDRAM写完成均确认后，按100MHz时间基准的30Hz节拍发布。像素域只在垂直消隐交接，确认后旧显示槽才重新用于写入；读取慢时保持上一完整帧。
- 1280×720输出沿用原工程约60.61Hz时序，30fps视频在显示帧边界量化交接，不将其称为严格每两次扫描换帧。

## 构建和验证

副板根目录运行：

```powershell
./scripts/build_tf_video.ps1 -TestOnly  # 只运行仿真
./scripts/build_tf_video.ps1            # 仿真、综合布线、时序门禁、生成位流
```

工具路径可通过 `-TD`、`-Iverilog`、`-Vvp`指定。仿真覆盖两种SD返回延迟、碎片化根目录与文件、跨簇/跨帧连续读、循环、坏头/短文件/坏簇链/传输错误、不完整帧禁止交接、暂停/继续及完整640×360到720p两帧逐像素对比。原控制器内部加密SDRAM电气模型与显示器物理显示仍以实板验证为准。

构建目录 `_build_tf_video` 保存真实仿真日志、时序/资源报告和输入SHA256快照；构建前后输入哈希不同则拒绝生成。时序失败、DRC异常或仿真日志过期也拒绝生成。成功种子保存到 `seed/tf_video` 后再交付。

用户已确认原候选能够播放，但播放时左侧出现间歇白点，KEY2暂停后消失；因此未完成画面质量验收，也未测得实际平均帧率。通过后再接回主板文物状态、暂停/速度/退出/应急及原PC HDMI路径。

## 左边界白点修复候选

候选：`secondary_tf_video_turnaround_guard8.bit`，SHA256 `3078dbe550d90fbd6a8d36fb81b82c1d879463773922a748371f7316119d7854`。seed=8，setup +0.105ns、hold +0.030ns、TNS均0；4962 LUT、3303寄存器、8 BRAM9K、0 DSP、2 PLL。完整回归、输入哈希及bitgen门禁通过，证据另存 `seed/tf_video/turnaround_guard8`；原候选bit和原成功种子不覆盖。

保持VIDEO0.BIN、640×360、30fps和HDMI时序不变，仅在本独立工程启用SDRAM读写换向保护：新突发启动检查控制器忙信号，最后写命令/最后读返回之后保留8个50MHz时钟的反向启动间隔（160ns）。不截除、涂黑或覆盖画面左边像素。参数默认关闭，正式博物馆入口不启用此保护。

`sim/tb_mvid_sdram_turnaround.v` 使用实际原厂CDC FIFO与抽象的延迟返回接口，检查双向交替、忙期间禁止启动、连续地址和512字读写数据顺序。GUARD=0且CHECK_BUSY=0的反向对照会报Missing read-to-write guard；GUARD=8通过。这验证调度约束，不模拟加密SDRAM的电气行为，不能据此宣称已复现或消除实板白点。

请使用单独命名的修复候选JTAG对照原版，至少完整播放一次并多次暂停/继续。TF文件不需要更换；正式release及Flash不动。

## 提高画质或帧率的边界

原始连续读卡实测约24.21MB/s，未包含文件访问和显示端并发开销。保留四个720p RGB565图片槽后，8MiB SDRAM仅剩1,015,808字节；现有两个视频槽占921,600字节。

| 候选格式（RGB565） | 视频载荷 | 两帧容量 | 当前判断 |
|---|---:|---:|---|
| 640×360 / 30fps | 13.824MB/s | 921,600字节 | 当前对照格式，继续完成稳定性验收 |
| 640×360 / 40fps | 18.432MB/s | 921,600字节 | 带宽候选，需修改帧率校验/发布节拍并实测；与约60.61Hz扫描节奏不整除 |
| 640×360 / 60fps | 27.648MB/s | 921,600字节 | 已超过当前原始读卡实测速率 |
| 768×432 / 30fps | 19.90656MB/s | 1,327,104字节 | 带宽可能够，但保留原图片槽时内存不够 |
| 1280×720 / 30fps | 55.296MB/s | 3,686,400字节 | 带宽和保留图片槽后的空间均不够 |

本次不同时提高分辨率或帧率，避免干扰白点对照。下一阶段可先评估替换2倍最近邻放大的滤波方式：能减轻块状边缘，但不增加源图细节，额外逻辑/行缓存仍需综合验证。独立演示工程可以重新划分更大视频槽，正式集成则必须协调原有图片槽，不能直接套用独立结果。
