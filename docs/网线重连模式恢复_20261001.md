# 同会话网线重连后 SW3 模式恢复

日期：2026-10-01。主板 `Anlogic`、副板 `Anlogic2`。本轮暂停资源优化，优先修复用户报告的真实双板控制回归；没有修改 TF 卡、音画时间轴、图序、主板显示或副板按键分配。

## 问题与依据

用户现象：拔插网线后拨动副板 SW3，主板 OSD 不改变自动/手动，SW3=1 再按主板 KEY2 仍进入自动讲解。

原副板 `mbp1_secondary_endpoint` 在 PHY 断线或两秒心跳超时时同时清除 `peer_boot_seen`、`hello_seen`、`peer_manual_cap`。原主板在对端 boot_id 改变或启动时发起 HELLO，不保证同会话重连重新发 HELLO。因此心跳及 DISPLAY_STATUS 恢复后，`control_ready` 可以重新有效，但 `manual_supported` 仍为0，副板拨码请求器禁止发送 0x17。

双端点仿真连接两板实际 codec、endpoint 和副板 keys，以应用替身执行模式命令；不手工补发能力包。未修复版本在短断线后复现 `alive=1 cap=0 ready=1`，模式保持旧值。此前端点单测断线后主动注入 HELLO，未覆盖此条件。

曾试验主板重发 HELLO，但超过重试周期的报文中断仍失败，未纳入交付。主板这项试验已完整撤回，主板 RTL、约束、工程入口及 bit 均保持原样。

## 最小修复

只改副板 `src/ethernet/mbp1_secondary_endpoint.v` 的断线/超时分支：

- 保留与已确认主板 boot_id 绑定的 HELLO 能力信息；不是盲目假定任何主板都支持手动模式。
- 心跳年龄立即置为超时，作废心跳/画面/诊断快照，取消旧控制及查询事务；离线不允许控制。
- 重连主动 HELLO、STATUS_QUERY；必须收到新的心跳和画面状态才能解锁，再用当前 SW3 与主板实际模式比较并发送绝对模式命令。
- 主板 boot_id 改变时沿用原分支，清除能力和旧事务，等待新 HELLO；新 HELLO 可以撤销手动能力，旧主板兼容不变。
- 不回放断线按键，不重置主板媒体，不改变 seq、CRC、端口、报文长度及原重试上限。

## 上板预期与操作

1. 只重烧副板新 bit，主板保持原正式版本，两板使用原 TF 卡并直连。
2. 在主板总览，副板 SW3=0，等待状态稳定；拔网线约1秒，断线期间拨到SW3=1，再插回。
3. 无需 KEY4、重新加载或重新上电；链路和状态恢复后，主板 OSD 应出现“手动”。再按主板KEY2，应静音、无字幕、不自动切图；主板KEY3可循环四图。
4. 反向测试：断线期间把SW3拨到0，重连后OSD应回到“自动”；如原来在手动展示，仍走原回全貌/收拢及轻量音频字幕恢复，等待就绪后再进入讲解。
5. 分别测试拔线超过3秒、SW3保持不动、模式命令发出后立刻拔线、主板讲解/转场中重连；忙时等待既有安全状态，不能承诺插线瞬间切模式。原四组调参和平移应在恢复后继续有效。
6. 建议循环至少10次，记录模式、OSD、音频/字幕及原控制是否正常。最终状态须看主板实际OSD，不仅看副板SW3位置。

应急期间副屏继续显示逃生图，用户已确认目前没有失联提示并选择暂缓显示改进；本轮没有增加该提示，不把它记为已通过。实际网线重连修复仍待用户实板确认。
