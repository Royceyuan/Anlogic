# 主板静音手动浏览与副板接口增量

日期：2026-10-01。更新：副板SW3仅负责模式，不再覆盖四键调参/平移；正式主板KEY3在手动展示中循环切图，KEY2退出回总览且保留缓存。手动→自动采用轻量音频/字幕会话恢复，不重读同一文物图片；KEY4仍为完整软复位。正常讲解基线为 `79037ed` 恢复的 `a0a6832`，负责人已验证基线功能及双板通信正常。电脑有线网卡仍故障，本文离线测试不依赖电脑连接实板。

## 1. 行为及后续副板控制

对应赛题基础功能的手动切图和自动轮播：复用现有讲解控制器、缓存及转场，不新增图像槽位、不改TF媒体格式、图片顺序或正常音画字幕时间轴。

| 副板状态 | 后续副板实现要求 |
|---|---|
| SW3=0 | 正常讲解；原SW2:SW1四组预设、参数、方向键分配不变；参数每按一次1档，方向每次20规范化源像素 |
| SW3=1 | 静音手动浏览；SW2:SW1四组预设、参数、方向键保持与自动模式相同；主板KEY3循环全貌→细节1→细节2→细节3→全貌 |
| SW4 | 保留副板现有本地展陈轮播的自动/手动切换，不断网；以副板当前工程说明为准 |

主板手动展示中：KEY1缩放、KEY2退出、KEY3循环切图、KEY4完整软复位。总览OSD、自动讲解暂停/波形及其他拨码功能不变。主板SW3仍是文物预载编号bit2，不是手动开关。

1. 在总览开启手动模式，仅设置模式，不自动进入。主板拨码选择预载文物，KEY1选择匹配高亮，KEY2进入；手动入口只要求图片缓存就绪，不要求WAV或字幕入口准备好。
2. 在正常讲解的稳定画面切入，保留当前图，停止旧音频并隐藏字幕和波形，清除暂停，避免暂停锁住手动转场。手动模式不自动推进或自然结束。主板KEY2通过已有“回全貌→收拢到总览”流程退出，不清除手动模式、不触发KEY4复位；预载拨码未变时保留四图缓存，可再次确认进入。若拨码已选择另一件，回总览后正常加载新目标，不属于KEY2软复位。
3. 正式主板KEY3在手动展示中循环四图，不切换隐藏的波形。副板四键不选图，始终调预设/参数/方向。图片已缓存，无需每次再读TF；复用原转场，不新增转场类型。`0x18`绝对图号接口保留用于兼容已有调试工具，但副板物理按键不调用它。
4. 手动期间暂停下一文物后台图片预载，保护当前四图；主板拨码变化仍是下一预载目标，退出后恢复原预载流程。当前展示文物不会随拨码变化。
5. 正常讲解的后台预载若已覆盖当前细节缓存，切入返回BUSY；正在读图或转场也不抢占事务。请先回总览并等待当前目标图片完整就绪，再开启并进入手动。建议先开启手动再按主板KEY2，避免这一边界。
6. 切回正常模式不续播旧音频：先回全貌再平滑收拢到总览，等待被取消的SD扇区收尾，仅重启音频与字幕会话；保留总览、同一文物图片、OSD名称和有效FAT32几何参数。不复位SD核、图片读取器、PLL、HDMI扫描或SDRAM控制器。音频FIFO复位期间不写入新PCM，旧扇区残留响应不附着到新会话；从头准备WAV及首条字幕后KEY2可进入。若拨码目标已改变，仍按原流程加载新文物。等待返回/轻量恢复期间心跳字节7 bit6=1，入口与新控制被阻止。重复“正常”命令不会重复准备。KEY4/应急仍走原完整恢复；副板按实际回报重新同步，不能仅按自身SW3猜测。

字幕只缓存当前/下一条，音频为FIFO流式读取，并非所有音频字幕永久驻留。因此“无图片预载”不等于“零读卡”；仍需少量根目录、音频头/PCM和首条字幕读取。更换或重新挂载TF卡后请按KEY4重新获取文件系统参数。

## 2. MBP1兼容增量

网络地址、CRC、版本1帧头、序号/会话、ACK及旧命令均不变。控制主板HELLO：`01 01 01 01 00 05 00 04 00 00 03 FF`，build_id=`0x00050004`，capability bit9表示手动浏览。未声明bit9的旧固件不发新命令。

### 0x17 BROWSE_MODE_SET，副→主，4字节，ACK_REQ

| 业务偏移 | 值 |
|---:|---|
| 0 | 0正常、1静音手动 |
| 1～3 | 必须为0 |

成功仅表示模式请求接受，不是转场完成。应急、恢复、转场、讲解结束流程、缓存不安全返回4 BUSY；非法模式/保留字段返回5 INVALID_STATE；长度错误返回2。模式改变时立即停止旧音频，退出时不恢复旧时间轴。

### 0x18 BROWSE_IMAGE_SET，副→主，4字节，ACK_REQ

| 业务偏移 | 值 |
|---:|---|
| 0 | 当前实际展示文物0～4，取HEARTBEAT字节1，不能用预载拨码代替 |
| 1 | 逻辑图号0全貌、1细节1、2细节2、3细节3 |
| 2～3 | 必须为0 |

只在已进入手动浏览、缓存完整、没有转场时接受。未开启手动/未进入/文物不匹配/图号越界/保留字段非0返回5；转场、恢复或缓存忙返回4。全貌仍映射实际物理槽0或4；不要直接将逻辑0作为视口命令的物理槽位。

### 实际状态回报

- DISPLAY_STATUS（0x16）仍12字节：字节6 bit2=`manual_mode`，总览也可能为1；bit0在手动时回报0，普通模式恢复保存的波形开关；其余字段不变。
- HEARTBEAT字节3和PLAYBACK_STATE字节1新增值5=静音手动浏览。转场仍优先报告3、返回过程中报告4；总览报告0。字节2/PLAYBACK_STATE字节2仍为物理槽0～4，总览255。
- 音频帧在手动浏览为0，不是暂停在旧进度；副屏不得继续滚动音频进度或显示旧字幕。
- HEARTBEAT已有高亮、拨码目标、缓存、可进入、恢复状态扩展保留。手动模式“可进入”只要求图片就绪，与正常模式要求音频字幕不同。
- 主板OSD保留名称、图阶段、源尺寸、倍率和画面参数；在ZOOM上方显示“自动/手动”。显示来自主板实际`manual_mode`，经两级同步后在帧边界更新，不直接显示副板拨码意图。副板SW3=1但面板仍显示“自动”时，模式尚未被主板接受；不要把它当作手动入口已生效。

### 固件匹配检查

副板SW3=1不会改变旧版主板固件的KEY2行为。两板都要烧录支持`0x17/0x18`的正式bit；副板须收到主板HELLO的capability bit9才会发送手动模式指令。主板仍烧录旧自动讲解版本、烧录单板诊断版本或尚未完成状态同步时，不能仅凭SW3位置断言进入了手动模式。建议在总览拨副板SW3=1，等待主板OSD出现“手动”后再按主板KEY2。主板自身SW3仍是文物预载编号，不作模式开关。

## 3. 后续副板事务规则

保持一条未确认控制事务。模式/图号使用绝对值，丢ACK按同seq、同payload重传；不能把重传解释成下一张。ACK成功后等待新的实际状态：

- 开启：字节6 bit2=1；若已在讲解，心跳须非转场且为静音状态5。
- 选图：文物匹配，DISPLAY_STATUS阶段与HEARTBEAT一致，逻辑0匹配物理0或4，其余匹配1/2/3；心跳非转场。
- 关闭：bit2=0且心跳阶段255/停止0、恢复标志bit6=0，使用请求发出至少100ms后收到的新心跳。模式关闭引发的返回/轻量恢复不取消该关闭事务，等待恢复结束后解锁；其他命令遇恢复仍取消。同一文物图片缓存保留，KEY2须等待音频和首条字幕就绪。不以ACK0立即切回“可调参”页面。

手动模式/切图事务的状态确认限时8秒，旧预设/调参/平移保留1.5秒。100ms未ACK重发，最多10次；保活和RX不阻塞。BUSY结束当前seq，不同seq重试需基于新快照：拨码模式意图可以在转场结束后重新发送，但不积压旧图号按键。长时间BUSY或缓存不完整提示“回总览后重试”，不得无限盲发。

启动、KEY4恢复或新会话后，先HELLO+查询状态，再比较SW3与主板实际模式决定是否发送新模式请求；旧待发命令丢弃。断线不猜测主板模式，不回放断线按键。副板四键在实际模式与SW3一致且主板处于安全状态时调参/平移，不发送图号命令。

同一主板启动编号下仅拔插网线时，主板不保证重新发送 HELLO。副板保留已确认且绑定该 boot_id 的能力信息，但断线/心跳超时立即取消旧事务、作废心跳和画面状态，并阻止控制；重连主动 HELLO/查询，必须收到新的心跳及 DISPLAY_STATUS 后才按当前 SW3 重新同步。主板 boot_id 改变时仍清除能力，等待新 HELLO，不向未知或不支持手动的固件发送 0x17。副板修复及板测步骤见 `Anlogic2/docs/网线重连模式恢复_20261001.md`，本次主板 RTL 和 bit 不变。
