# MAIN-5D 控制修复验证

## 范围与根因

本轮保留音画字幕时间轴、图片素材和现有转场；只修复控制交互及其显示路径。PC 是副板协议模拟器，不是最终产品依赖。

- 命令 valid 在完成握手前保持有效，媒体端旧逻辑可能重复处理同一命令；新增一次性接收标志，并等待视频域确认后返回结果。
- 命令接收后若恰逢转场，视频域旧路径可能不退出等待。现在每次请求在帧边界明确应用或返回 BUSY，不能永久占用事务。
- 暂停冻结的是讲解进度和普通转场，不再冻结用户主动发起的直接缩放、视口切换。
- PC 原先把所有错误模式均视作不可控制；字幕错误不代表图像控制不可用。保留错误提示，解除该误拦截。
- PC 按新目标状态回报解除等待，包括状态先于 ACK 到达的情况；不再追加固定等待。1.5 秒未确认时提示结果未知并解除等待，不自动重放旧命令。

## 约定

- KEY1：讲解播放或暂停时直接切换 1×/2×；普通转场、应急和恢复期间仍禁止切换。
- 远程视口：播放或暂停、1×/2× 均可操作。1× 平移露底，2× 不越过源图范围；小步 20、大步 40 个规范化 960×540 源像素。X 限定 ±240、Y 限定 ±135；换阶段、倍率、返回总览时归中。
- 图像参数档位不变，仅 PC 和 OSD 改为百分比。亮度为满量程加性偏移；色温为负冷正暖的相对强度，不是 Kelvin。
- 副板继续用 MBP1 的绝对目标命令、ACK、DISPLAY_STATUS；不使用连发增量推测主板状态。细节见双板联调计划。

保留的工具告警与旧版相同：`derive_pll_clocks` 弃用提示、PLL feedback 路径提示及 SDRAM_CLK 输出的一个已标记局部时钟路由。不是“零警告”构建。最终 STA 和 DRC 原始报告见 `docs/reports/main5d_control_repair_*`。

复现：在工程根目录将 `scripts/build_main5d_control_repair.tcl` 逐行管道输入 `D:\TD_6.2.1\bin\td_commands_prompt.exe`，确认无错误后同样执行 `scripts/build_main5d_control_repair_bitgen.tcl`。TD 可能在报告错误后仍返回退出码 0，必须同时检查日志、时序和布线状态，不能只看进程退出码。

实板仍须按 PC 控制面板验收文档逐项检查；仿真或 bitgen 不代表 BOARD PASS。
